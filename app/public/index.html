NGINX cases

N1

Load balancing

200

NGINX opens a new connection to the Service for every request, so Kubernetes can pick a different ready pod each time.

Not run yet.

N2

Keep-alive pinning

200

A route that reuses upstream connections tends to stay on one pod, because the Service balances connections, not requests.

Not run yet.

N3

App error passthrough

5xx / 4xx

The app returns an error status. NGINX forwards the app's response unchanged; it is not a gateway failure.

Not run yet.

N4

Gateway timeout

200 / 504

This route has a 5 s proxy_read_timeout. A slower app answer is cut off and NGINX returns its own 504.

Not run yet.

N5

Rate limiting

200 + 429

/api/limited allows 2 requests/s with a burst of 3. Extra requests are rejected by NGINX and never reach a pod.

Not run yet.

N6

Who answered?

200 / 404

/nginx-health is answered by NGINX alone. An unknown API path is forwarded and the app replies 404.

Not run yet.

N7

No ready endpoints

502 → 200

Every pod withdraws readiness for 20 s. The Service has no endpoints, NGINX returns 502, then traffic recovers without anyone intervening.

Not run yet.

Kubernetes cases

K1

Readiness failure

pod stays, gets no traffic

The pod that receives this request fails its readiness probe for 30 s. It keeps running but leaves the Service endpoints.

Not run yet.

K2

Container crash

RESTARTS +1

The process exits with code 1. The kubelet restarts the container in the same pod, so the pod name stays the same.

Not run yet.

K3

Liveness failure

restart after ~30 s

The process keeps running but its liveness probe starts failing. After 3 failed checks, 10 s apart, the kubelet kills and restarts it.

Not run yet.

K4

Pod deleted

new pod name

A pod is removed. The ReplicaSet notices it is below the desired count and creates a replacement with a new name.

Not run yet.

K5

Scaling

replicas change

Change the desired replica count. New pods take traffic only once they are ready; removed pods drain first.

Not run yet.

K6

Rolling update

zero downtime

Every pod is replaced in turn (maxSurge 1, maxUnavailable 1). Keep sending requests: they should keep succeeding.

Not run yet.

Beyond the buttons

Cases you trigger from a terminal

The page shows the result live

NGINX itself goes down

kubectl delete pod -l app.kubernetes.io/name=kubescale-nginx

The browser gets no HTTP response at all, so the topbar shows NGINX unreachable. Compare with N7, where NGINX is up but has nothing behind it. The NGINX Deployment replaces the pod within seconds.

Bad image rollout

kubectl set image deployment/kubescale-app app=kubescale-demo:missing
kubectl rollout undo deployment/kubescale-app

New pods show ErrImageNeverPull because imagePullPolicy is Never. The rollout stalls, and the old ready pods keep serving.

Broken release (never ready)

kubectl patch configmap kubescale-app-config -p '{"data":{"HEALTH_MODE":"unhealthy"}}'
kubectl rollout restart deployment/kubescale-app
# restore
kubectl patch configmap kubescale-app-config -p '{"data":{"HEALTH_MODE":"healthy"}}'
kubectl rollout restart deployment/kubescale-app

New pods run but never become ready. With maxUnavailable: 1, one old pod is removed and the rollout then stops. The page shows reduced capacity and readiness-probe warnings, not a full outage.

Not enough capacity

kubectl scale deployment/kubescale-app --replicas=40
kubectl scale deployment/kubescale-app --replicas=3

When the node runs out of CPU for the 50m requests, extra pods stay Pending and events show FailedScheduling. Pods that are already running are not affected.
